# 遭遇战地图行星触发器探针

2026-10-01，游戏 1.15 隔离副本，基于双星咽喉地图。此文件记录技术证据，尚未接受为多数胜利机制。

本机内置任务地图使用 `unitDetect`、`unitAdd`、`objective` 与 `winCondition=requiredObjectives`。先在遭遇战地图隔离副本放置一个 `unitAdd`，延迟 2 秒生成本队护卫舰；12 秒存档出现新护卫舰，证明遭遇战执行普通触发器。再预置一座本队 `rsColony`，添加覆盖全图、限制 `team=0`、`unitType=rsColony`、`minUnits=1` 的 `unitDetect`，让另一个 `unitAdd` 由其 `activatedBy` 触发。存档出现预置殖民地 (850,910) 与由检测器生成的科研船 (1210,1610)，同时保留独立的延迟护卫舰 (1010,1610)。可确认遭遇战会按队伍和殖民地类型检测，并触发后继动作。

探针只在忽略的 `work/game-sandbox` 中运行，没有将测试舰或触发器放进正式地图。首轮测试尚未覆盖检测条件消失后的计时、任务目标判胜和动态多数门槛；后续结果见下文。正式设计仍要求分值只对应现有殖民地，且不能在所有行星失效时僵局。

后续隔离测试给检测器设 `warmup=5s`，并让初始殖民地 2 秒后自动删除。12 秒墙钟时间的存档仅见独立延迟护卫舰，没有检测奖励；这排除了“检测到一瞬间就永久满足计时”的情况。再让地图 5 秒后在另一位置生成一座不会自动删除的殖民地：较早存档有新殖民地而无奖励，23 秒墙钟时间存档有奖励科研船，说明失去条件后计时可重新开始。墙钟时间包含游戏启动，不能把它当作精确的游戏内 5 秒测量。

将隔离地图的 `map_info.winCondition` 设为 `requiredObjectives`，并加入由上述检测器激活的 `objective` 后，游戏日志出现 `Found objective: Colony held` 与 `objective met`。截至随后存档，日志没有胜利事件；因此这只能证明遭遇战会解析并达成任务目标，**不能证明多人遭遇战按此目标结束**。正式地图仍保持原有胜利规则，须另测游戏内胜利状态和多队行为。
